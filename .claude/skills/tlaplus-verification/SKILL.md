# TLA+設計検証スキル

TLA+形式言語を用いて、設計ドキュメントの状態遷移・並行性・時相論理を形式的に検証するスキルです。

## スキルの目的

- 設計ドキュメント（PRD、機能設計書、アーキテクチャ設計書）の振る舞い的性質を形式的に検証する
- 状態遷移の健全性、並行プロセスの正しさ、時相性質を検出する
- 検証結果を `.steering/` 配下に中間データとして体系的に記録する

## 入力となる設計書（メインエージェントが読み込む）

`docs/` 配下の設計書はメインエージェント（`verify-design-tlaplus` コマンド）がステップ2で読み込みます。サブエージェント（`tlaplus-design-verifier`）はこれらを直接読みません。

### 自己完結的な design.md の原則

`design.md` は、サブエージェント（`tlaplus-design-verifier`）が読む唯一の設計仕様書です。サブエージェントは `docs/` 配下の設計ドキュメントを直接読みません。

そのため、メインエージェント（コマンド）が `design.md` を作成する際に、上記設計書から検証に必要な設計コンテキスト（エンティティ定義、状態遷移、並行プロセスなど）を抽出し、`design.md` の「設計コンテキスト」セクションに凝縮して記載します。これにより：

- サブエージェントが大量の設計ドキュメントを毎回読み込む必要がなくなる
- `design.md` だけで TLA+ コード生成に必要な情報が全て揃う
- サブエージェントの実行が高速化される

## 出力（.steering配下の中間データ）

検証実行時に `.steering/[yyyyMMddHHmm]-verify-[検証名]/` (日時はISO 8601形式、Bash('date "+%Y%m%d%H%M"')の戻り値) 配下に以下を出力します：

| ファイル | 説明 |
|---------|------|
| `requirements.md` | 開発者の指定を詳細化・網羅化した検証項目一覧 |
| `design.md` | 各検証項目をTLA+で検証するためのモデル設計 |
| `tasklist.md` | タスクリストと進捗管理、振り返り |
| `[検証項目名].tla` | 検証項目ごとのTLA+ソースコード（複数ファイル可） |
| `[検証項目名]-results.md` | 各TLA+コードの実行結果と解釈 |

## 検証可能な設計特性の例

### 状態遷移関連

- **到達可能性**: 全ての状態が初期状態から到達可能か
- **デッドロックの不在**: 行き止まりの状態がないか
- **不正遷移の排除**: 許可されていない状態遷移が存在しないか

### 並行性関連

- **相互排除**: 共有リソースへの同時アクセスが排除されているか
- **デッドロックフリー**: 並行プロセスが互いにブロックし合わないか
- **飢餓フリー**: 全てのプロセスがいずれサービスを受けられるか

### 時相論理関連

- **活性（Liveness）**: いずれ必ず目標状態に到達するか（`<>P`）
- **公平性（Fairness）**: 有効なアクションがいずれ必ず実行されるか（`[]<>P`）
- **進行性（Progress）**: ある状態から別の状態へ必ず進むか（`P ~> Q`）

### 安全性関連

- **不変条件**: システムが常に満たすべき性質（`[]P`）
- **順序制約**: 操作の実行順序が設計通りか

## 使用方法

### コマンド経由

```bash
> /verify-design-tlaplus 状態遷移の健全性
> /verify-design-tlaplus 並行処理の安全性
> /verify-design-tlaplus リソース競合の排除
```

### スキル直接呼び出し

`Skill('tlaplus-verification')` で呼び出す場合、以下のモードがあります。

#### モード1: 検証計画（ステアリングファイル作成）

検証項目を洗い出し、TLA+モデルの設計を行います。

**手順:**
1. 設計ドキュメント（3つ）を読み込む
2. ユーザーの検証要求を分析し、検証項目を詳細化・網羅化
3. テンプレートから `requirements.md` を作成
4. 設計ドキュメントから検証に必要な設計コンテキストを抽出し、各検証項目のTLA+モデルを設計して、テンプレートから `design.md` を作成（自己完結的な仕様書として）
5. テンプレートから `tasklist.md` を作成し、検証項目ごとのタスクを具体化

#### モード2: 検証実行（検証項目ごとのサブエージェント委譲 + tasklist管理）

検証項目（V-1, V-2, ...）ごとに個別の `tlaplus-design-verifier` サブエージェントを起動し、TLA+実装・実行・結果記録を委譲します。サブエージェントはステアリングディレクトリ内のファイル（`requirements.md` と `design.md`）のみを読み込みます。サブエージェントの返却結果は「検証結論」と「設計への示唆」のみに限定し、トークン数を節約します。

**手順:**
1. `tasklist.md` のフェーズ1から検証項目リストを取得
2. 各検証項目について `tlaplus-design-verifier` サブエージェントを1つずつ起動し、`.tla` 実装・実行・`-results.md` 生成を委譲
3. 各サブエージェント完了後、返却された検証結論と設計への示唆を保持し、`tasklist.md` のフェーズ1タスクを `[x]` に更新
4. フェーズ2（結果分析）のタスクをメインエージェントがtasklist駆動ループで実行（`-results.md` は読み込まず、サブエージェント返却結果を使用）

#### モード3: 振り返り

検証結果をまとめ、`tasklist.md` に振り返りを記録します。

**手順:**
1. フェーズ2で整理した検証結論と設計への示唆を総合分析（`-results.md` は読み込まない）
2. `tasklist.md` の振り返りセクションを更新
3. ユーザーに最終レポートを報告（設計ドキュメントの語彙で記述）

## TLA+モデル設計のガイドライン

### 設計概念からTLA+へのマッピング

| 設計概念 | TLA+構成要素 | 例 |
|---------|-------------|-----|
| エンティティの状態 | `VARIABLE` | `VARIABLE botState` |
| 許容される状態値 | 型不変条件 | `TypeOK == botState \in {"idle","mining"}` |
| 状態遷移ルール | Actionプレディケート | `StartMining == botState = "idle" /\ botState' = "mining"` |
| システム制約 | INVARIANT | `INVARIANT SafetyProp` |
| いずれ必ず起こる | PROPERTY（時相性質） | `PROPERTY <>completed` |
| 並行プロセス | PlusCal process | `process bot \in Bots` |
| 構成パラメータ | CONSTANT | `CONSTANTS MaxBots, MaxTasks` |

### アプローチ選択（Pure TLA+ / PlusCal）

各検証項目ごとにどちらのアプローチを使うか指定する。

| 特徴 | 推奨アプローチ |
|------|-------------|
| 単一エンティティの状態機械 | Pure TLA+ |
| 複数プロセスの並行動作 | PlusCal |
| 共有リソースの競合 | PlusCal |
| 時相性質（公平性条件付き） | Pure TLA+ |
| 抽象的なシステムレベル性質 | Pure TLA+ |

### スコープ（TLC CONSTANTS）の目安

| 規模 | CONSTANTS | state constraint | symmetry |
|------|-----------|-----------------|----------|
| 小（2-3プロセス） | 直接値 `N = 2` | 不要 | 適用可能なら |
| 中（3-5プロセス） | `N = 3` | 推奨 | 推奨 |
| 大（5+プロセス） | `N = 3` + symmetry | 必須 | 必須 |

### 検証項目の命名規則

ファイル名に使う検証項目名は、以下の規則に従います：

- **英語のケバブケース**: `state-transition`, `mutual-exclusion`, `liveness-property`
- **短く具体的に**: 何を検証するかが名前から分かること
- **動詞は避ける**: `check-state` ではなく `state-transition`

## テンプレート

- `templates/requirements.md` — 検証項目一覧のテンプレート
- `templates/design.md` — TLA+モデル設計のテンプレート
- `templates/tasklist.md` — タスクリストと振り返りのテンプレート
- `templates/results.md` — 検証結果のテンプレート（Markdown形式、実行結果はコードブロックで埋め込み）
