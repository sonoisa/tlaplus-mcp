### TLC Config設計

```json
{
  "init": "{Init述語名}",
  "next": "{Next述語名}",
  "invariants": ["{不変条件1}", "{不変条件2}"],
  "properties": ["{時相性質1}"],
  "constants": {"{CONSTANT名}": "{値}"},
  "stateConstraint": "{状態制約式（必要な場合）}",
  "symmetry": "{対称性集合名（必要な場合）}"
}
```

> **SPECIFICATION モードの使い分け**:
> - **INIT/NEXT モード**（上記）: 安全性検証（INVARIANT のみ）に使用。`init` と `next` を指定。
> - **SPECIFICATION モード**: 時相性質（PROPERTY）や公平性条件（WF/SF）を含む検証に使用。`specification` を指定し、`init`/`next` は省略。
>
> SPECIFICATION モードの TLC Config 例:
> ```json
> {
>   "specification": "Spec",
>   "invariants": ["{不変条件1}"],
>   "properties": ["{時相性質1}"],
>   "checkDeadlock": false
> }
> ```
>
> - `checkDeadlock: false` は、終端状態（Next が無効な状態）を持つ状態機械でデッドロック検出を無効化する場合に使用。
